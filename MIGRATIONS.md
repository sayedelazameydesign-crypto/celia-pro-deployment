# 🗄️ Database Migrations Guide

This guide explains how to manage database schema changes using Alembic.

## 📋 Overview

We use **Alembic** for database migrations to:
- Track schema changes over time
- Apply migrations safely without data loss
- Support both development (SQLite) and production (PostgreSQL)
- Enable rollbacks when needed

## 🚀 Quick Start

### Apply all pending migrations
```bash
cd backend
alembic upgrade head
```

### Create a new migration
```bash
cd backend
alembic revision --autogenerate -m "description of changes"
```

### Check migration status
```bash
cd backend
alembic current
alembic history
```

### Rollback last migration
```bash
cd backend
alembic downgrade -1
```

## 🔧 Configuration

### Development (SQLite)
The default configuration uses SQLite:
```ini
# alembic.ini
sqlalchemy.url = sqlite+aiosqlite:///./celia_dev.db
```

### Production (PostgreSQL)
For production, set the `ALEMBIC_DB_URL` environment variable:
```bash
export ALEMBIC_DB_URL=postgresql+asyncpg://user:pass@localhost/celiadb
alembic upgrade head
```

## 📝 Creating Migrations

### 1. Make changes to models
Edit `database/models.py`:
```python
class NewModel(Base):
    __tablename__ = "new_table"
    id = Column(String, primary_key=True)
    # ... other columns
```

### 2. Generate migration
```bash
alembic revision --autogenerate -m "add new_table"
```

This creates a new file in `alembic/versions/` with:
- `upgrade()` function to apply changes
- `downgrade()` function to rollback

### 3. Review the migration
Open the generated file and review:
- ✅ Correct tables/columns are being created
- ✅ Indexes are being created
- ✅ Foreign keys are correct
- ✅ Downgrade will properly reverse the changes

### 4. Apply the migration
```bash
alembic upgrade head
```

## 🔄 Migration Workflow

### Development Workflow
1. Make model changes
2. Generate migration: `alembic revision --autogenerate -m "description"`
3. Review migration file
4. Apply: `alembic upgrade head`
5. Test the changes
6. Commit both model changes and migration file

### Production Workflow
1. Deploy code changes (including migration files)
2. Run migrations: `alembic upgrade head`
3. Verify application works
4. If issues, rollback: `alembic downgrade -1`

## ⚠️ Best Practices

### DO ✅
- Always review autogenerated migrations before applying
- Test migrations on a copy of production data first
- Keep migrations small and focused
- Include both upgrade and downgrade functions
- Test rollbacks regularly
- Commit migration files to version control

### DON'T ❌
- Don't edit applied migration files
- Don't skip migrations
- Don't manually modify the database schema
- Don't delete migration files from `versions/`
- Don't rename migration files

## 🐛 Troubleshooting

### Migration fails with "Target database is not up to date"
```bash
alembic upgrade head
```

### Need to start over (development only!)
```bash
rm celia_dev.db
alembic upgrade head
```

### Migration conflict
If you see "Multiple heads" error:
```bash
alembic heads  # See all heads
alembic merge -m "merge migrations" <head1> <head2>
alembic upgrade head
```
